5. curriculum_2027.csv 형식
==================================================

첫 줄 헤더:

entry_year,grade,semester,course_name,course_code,completion_type,credits,notes


예시:

2027,1,1,해부생리학1,ADB101,전선,2,

2027,1,1,약학기초생물학1,ADB002,전선,3,


각 컬럼 의미:

entry_year
→ 입학연도

grade
→ 1~6학년

semester
→ 1 또는 2

course_name
→ 공식 과목명

course_code
→ 대표 학정번호
→ 확실하지 않으면 빈칸 가능

completion_type
→ 전필 또는 전선

credits
→ 공식 학점
→ 확실하지 않으면 빈칸 가능

notes
→ 판단 근거
→ 학정번호 출처
→ 과목명 변경 여부
→ 학점 변경 여부 등을 기록


현재 importer가 검사하는 조건:

grade는 1~6만 허용

semester는 1 또는 2만 허용

completion_type은 전필 또는 전선만 허용

한 CSV에는 하나의 entry_year만 허용

동일한 grade + semester + course_name 중복 금지

credits는 숫자 또는 빈 값

6. 학정번호와 학점 보강
==================================================

실제 수강편람 데이터를 참고한다.


현재 과거 수강편람 이력 파일:

파일 열기:

code data/2022_2026_pharmacy_course_history.csv


또는 SQLite DB에서 직접 검색한다.


실행:

sqlite3 data/db/inyak.db


예시 SQL:

SELECT
    academic_year,
    semester,
    course_code,
    course_name,
    completion_type,
    credits
FROM courses
WHERE course_name LIKE '%독성학%'
ORDER BY academic_year, semester;


종료:

.quit

7. 교육과정과 실제 수강편람이 다를 때
==================================================

바로 실제 수강편람 값으로 덮어쓰지 않는다.


먼저 확인할 것:

1) 정말 같은 과목인지

2) 학정번호가 변경된 것인지

3) 과목명이 변경된 것인지

4) 교육과정 개편으로 학점이 바뀐 것인지

5) 같은 이름의 다른 과목인지

6) 교육과정 PDF 표기 문제인지


애매하면 notes에 근거를 남긴다.

9. 전공 교육과정 import 결과 확인
==================================================

실행:

sqlite3 data/db/inyak.db


전체 과목 확인:

SELECT
    entry_year,
    grade,
    semester,
    completion_type,
    course_code,
    course_name,
    credits
FROM curriculum_courses
WHERE entry_year = 2022
ORDER BY grade, semester, completion_type, course_name;


과목 수 확인:

SELECT COUNT(*)
FROM curriculum_courses
WHERE entry_year = 2027;


전필/전선 개설학점 합계 확인:

SELECT
    completion_type,
    COUNT(*) AS course_count,
    SUM(COALESCE(credits, 0)) AS credits
FROM curriculum_courses
WHERE entry_year = 2022
GROUP BY completion_type;


종료:

.quit


주의:

curriculum_courses 안의 전필/전선 학점 합계와
공식 졸업 최소학점은 반드시 같을 필요가 없다.

공식 최소 이수학점은 graduation_requirements에서 따로 관리한다.

10. 교육과정 audit 실행
==================================================

실행:

python scripts/audit_curriculum_credits.py


이 스크립트는 현재 DB에 들어 있는 모든 curriculum_courses를
실제 courses 데이터와 비교한다.


주요 출력:


[CREDIT_MISMATCH]

→ 교육과정상의 학점과 실제 수강편람 학점이 다름


[NOT_FOUND]

→ 학정번호로 실제 개설 과목을 찾지 못함

이 경우 같은 학기 또는 같은 학년도에서
이름 기준 후보를 같이 보여준다.


[SECTION_CREDIT_CONFLICT]

→ 같은 학정번호인데 분반별 학점이 서로 다름


마지막 요약:

교육과정 과목 수
현재 검증 가능
아직 검증 불가
학점 일치
학점 불일치
학정번호로 찾지 못함
분반 간 학점 충돌

17. general_education_areas_2027.csv 형식
==================================================

헤더:

entry_year,category,area_name,minimum_credits,is_required,notes,display_order


컬럼 의미:

entry_year
→ 입학연도

category
→ 기초교양 또는 균형교양

area_name
→ 세부 영역 이름

minimum_credits
→ 해당 영역 최소학점
→ 없으면 빈칸

is_required
→ 필수 영역이면 1
→ 선택 영역이면 0

notes
→ 추가 조건

display_order
→ 화면 표시 순서


형식 예시:

2027,기초교양,사고,2,1,,1

2027,기초교양,언어와 표현,2,1,글쓰기 영역,2

2027,균형교양,인간과 예술,,0,,1

19. 교양 import 결과 확인
==================================================

실행:

sqlite3 data/db/inyak.db


교양 대분류:

SELECT *
FROM general_education_requirements
WHERE entry_year = 2027
ORDER BY display_order;


교양 세부 영역:

SELECT
    ger.entry_year,
    ger.category,
    gea.area_name,
    gea.minimum_credits,
    gea.is_required,
    gea.display_order
FROM general_education_areas AS gea
JOIN general_education_requirements AS ger
    ON ger.id = gea.requirement_id
WHERE ger.entry_year = 2027
ORDER BY ger.display_order, gea.display_order;


종료:

.quit

31. migrate_inyak_to_postgres.py 주의
==================================================

현재 존재하는 스크립트:

scripts/migrate_inyak_to_postgres.py


이 스크립트의 목적:

로컬 SQLite의 공용 데이터를
비어 있는 PostgreSQL DB로 최초 이전


복사 대상 테이블:

courses

curriculum_courses

graduation_requirements

general_education_requirements

general_education_areas


중요:

대상 PostgreSQL 테이블에 이미 데이터가 있으면
안전장치 때문에 실행이 중단된다.


따라서 이미 사용 중인 Supabase DB에
새 학번 하나만 추가하려고
이 스크립트를 실행하면 안 된다.


잘못된 용도:

python scripts/migrate_inyak_to_postgres.py


이것은 연례 교육과정 증분 업데이트용 스크립트가 아니다.

특정 학번만 안전하게 넣는 전용 스크립트가 필요하다.


예시 이름:

scripts/sync_cohort_to_postgres.py


필요한 기능:

DATABASE_URL 확인

연결 대상 DB 표시

개발 DB / 배포 DB 구분 확인

입력할 entry_year 표시

해당 학번 데이터만 처리

다른 학번 데이터는 절대 삭제하지 않음

transaction 사용

실패 시 rollback

import 전후 row count 출력

가능하면 --dry-run 지원


이 기능이 생기기 전까지는

“로컬 SQLite import 완료”

와

“Supabase 반영 완료”

를 같은 것으로 보면 안 된다.

33. 현재 dev 기준 데이터 상태
==================================================

현재 GitHub dev의 data/seed에서 확인되는 파일:

data/seed/curriculum/curriculum_2023.csv

data/seed/curriculum/curriculum_2024.csv

data/seed/general_education/general_education_requirements_2023.csv

data/seed/general_education/general_education_requirements_2024.csv

data/seed/general_education/general_education_areas_2023.csv

data/seed/general_education/general_education_areas_2024.csv


현재 graduation_requirements.csv에는
2023, 2024, 2025, 2026 행이 존재한다.


즉 현재 dev에서는

2025/2026 전공 curriculum seed

2025/2026 교양 seed

가 보이지 않는다.


따라서 나중에
2025/2026 데이터가 어떤 경로로 DB에 들어갔는지 확인하고

seed 파일을 source-of-truth로 맞추는 정리 작업이 필요하다.

공식 교육과정 자료를 확보했는가

semester가 1 또는 2인가

학점 근거를 확인했는가

미래 과목을 검증 불가라는 이유로 삭제하지 않았는가

import_curriculum.py가 성공했는가

audit 결과를 검토했는가

공식 전필 최소학점을 확인했는가

공식 전선 최소학점을 확인했는가

graduation_requirements.csv에 새 학번을 추가했는가

load_graduation_requirements.py가 성공했는가

교양 대분류 요건을 확인했는가

git diff에 예상하지 않은 변경이 없는가

필요한 파일만 stage했는가

commit 후 dev에 push했는가

Supabase 반영 여부를 별도로 확인했는가

migrate_inyak_to_postgres.py를 증분 업데이트 용도로 실행하지 않았는가

36. 이 작업에서 지켜야 할 원칙
==================================================

1) 공식 교육과정 자료가 기준이다.

2) 실제 수강편람은 검증 자료다.

3) 미래 학년 과목은 실제 개설 데이터가 없어도
   공식 교육과정에 있으면 유지한다.

4) 전공 교육과정 개설학점 합계와
   공식 졸업 최소학점을 같은 값으로 취급하지 않는다.

5) 로컬 SQLite import와
   Supabase 반영은 현재 서로 다른 단계다.

6) 기존 학번 데이터를 건드리지 않고
   새 학번 데이터만 추가 또는 교체하는 방향으로 작업한다.
